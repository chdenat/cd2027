# Font Awesome Configuration

## Integration

- **Method:** Named Font Awesome icon imports from npm packages, adapted to Web Awesome `<wa-icon>` through a small custom icon library.
- **Version:** 7.3.1 (`@fortawesome/pro-solid-svg-icons` and `@fortawesome/free-brands-svg-icons`).
- **License:** Pro.
- **Families:** Classic solid icons and brand icons used by the site.

## Defaults

- **Style:** Solid.
- **Family:** Classic.

## Import Pattern

`scripts/fontawesome-icons.entry.js` imports only the icon definitions used by the site. `bun run build:icons` bundles those imports to an ignored build artifact, which Eleventy copies to the generated site. `src/assets/fontawesome-library.js` registers a Web Awesome icon library that resolves names to those imported definitions. Templates use `<wa-icon library="pro">`; the site does not copy the package's SVG or webfont directories and does not use a Kit or CDN.

Use `<wa-icon library="pro" name="book-open" variant="solid" aria-hidden="true"></wa-icon>` for a solid icon and `family="brands"` for a brand. Add each new icon definition to `scripts/fontawesome-icons.entry.js` and rebuild with `bun run build:icons`.

## Conventions

- Place button icons in the `start` or `end` slot and keep decorative icons hidden from assistive technology.
- Give icon-only controls an accessible label.
- Keep Font Awesome icons inside Web Awesome controls where applicable; do not introduce another icon library.
- Keep this configuration in version control so future icon additions use the same integration.
- CI must provide the `FONTAWESOME_PACKAGE_TOKEN` secret to install the private Pro package.
